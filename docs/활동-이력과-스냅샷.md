# 활동 이력과 스냅샷

## 1. 목적

매 기상에 따른 활동 내역과 각 단계의 변화를 스냅샷으로 남깁니다. LLM과 사용자, 개발자가 과거부터 현재까지 비서가 어떤 상황을 파악했고 무엇을 변경·수행했는지 시간 순서와 상황의 흐름에 따라 열람할 수 있어야 합니다.

Git의 커밋처럼 이전 상태와의 관계, 변경 내용, 변경 이유를 추적하는 경험을 지향합니다. 실제 Git을 기록 저장 수단으로 채택하거나 브랜치·병합·되돌리기를 구현한다는 결정은 아닙니다.

## 2. 작업기억과 이력의 구분

| 구분 | 역할 |
| --- | --- |
| 작업기억 | 현재 사용자를 이해하고 다음 활동을 진행하기 위한 최신 상태 |
| 활동 이력·스냅샷 | 각 시점의 상태와 그 상태에 이른 변화를 확인하는 과거 기록 |
| 목표 종료 보고서 | 특정 목표의 생성부터 종료까지를 정리한 정적인 결과물 |

작업기억이 갱신되거나 목표·작업이 진행 중인 목록에서 빠져도 과거 기록은 함께 덮어쓰거나 없어지지 않습니다. 목표 종료 보고서는 관련 스냅샷을 참조합니다.

## 3. 기록 범위

### 회차 단위

- 언제, 어떤 계기로 깨어났는지.
- 이번 회차에서 파악한 상황과 참조한 맥락.
- 어떤 단계들을 거쳤고, 전체적으로 무엇이 바뀌었는지.
- 실제 작업과 사용자 소통, 남은 일, 다음 기상 결정.
- 회차가 정상적으로 마무리되었는지, 중간에 중단되었는지.

### 단계 단위

- 어떤 활동 회차의 어느 단계인지와 기록 시점.
- 해당 단계가 참조한 상태·근거의 요약.
- 새로 추가·변경·종료한 정보와 이전 상태와의 차이.
- 선택한 결정과 그 이유의 요약.
- 실제 실행하거나 전달한 내용과 확인된 결과.
- 작업 없음·변경 없음·보류·실패 등 해당 단계의 결과.

단계에서 할 일이 없더라도 ‘변경 없음으로 통과했다’는 사실은 확인할 수 있어야 합니다. 동일한 전체 상태를 반복 복제할지 여부와 구체적인 스냅샷 저장 형식은 이후 정합니다.

## 4. 스냅샷이 표현할 상태

현재 상태만 보여주는 것이 아니라, 선택한 과거 시점에 어떤 상태였는지와 그 전후에 무엇이 달라졌는지 확인할 수 있어야 합니다.

대상에는 관련 컨텍스트 변화분, 기간별 작업기억, 목표와 출처·발생 경로·이유, 계획·작업 상태, 사용자 소통 결과, 기상 예약의 변경 등이 포함됩니다. 모든 원본 데이터를 매번 복사한다는 뜻은 아닙니다. 어떤 정보를 상태에 포함하고 어떤 근거를 참조로 연결할지는 이후 정합니다.

기록하는 판단 근거는 설명 가능한 결정 요약입니다. LLM의 내부 추론 전문을 보존하는 명세는 아닙니다.

## 5. 기록 원칙

- 한 회차의 여러 단계 기록과 이전·다음 회차 기록을 서로 연결합니다.
- 목표·작업·소통과 연결하여 특정 대상의 변화도 따라갈 수 있게 합니다.
- 계획과 실제 실행, 전달 시도와 사용자 확인, 추론과 관측 사실을 구분합니다.
- 이후에 사실을 정정하더라도 과거 기록을 현재 사실에 맞게 조용히 바꾸지 않습니다. 정정 내용과 관련 과거 기록을 연결합니다.
- 중단된 활동을 완료된 것처럼 기록하지 않습니다. 종료 기록이 없을 때 확인 가능한 마지막 상태를 구분합니다.
- 스냅샷 열람은 과거 상태를 확인하는 기능입니다. 이미 수행한 외부 행동까지 되돌릴 수 있다는 의미는 아닙니다.

활동 이력을 남기는 것은 LLM이 필요할 때만 선택하는 작업이 아니라 활동 루프 전반의 공통 책임입니다. LLM이 기록할 내용을 구성하는 역할과 기록을 누락 없이 보존하는 서비스의 역할은 세부 설계에서 구체화합니다.

## 6. 열람 경험

LLM과 사용자, 개발자가 필요할 때 기록을 조회하고 다음 흐름을 확인할 수 있어야 합니다. 개발자의 접근은 사용자가 허용하는 범위를 따르며 자동으로 외부 전송되는 개발자용 기록을 의미하지 않습니다.

| 열람 관점 | 확인할 내용 |
| --- | --- |
| 시간 흐름 | 특정 날짜나 회차 전후로 비서의 상황 이해와 활동이 어떻게 달라졌는가 |
| 회차·단계 | 이번 기상에서 각 단계가 무엇을 바꾸었고 왜 그렇게 했는가 |
| 목표·작업 | 목표가 어떻게 생겨나 어떤 작업과 수정을 거쳐 종료되었는가 |
| 상태 비교 | 선택한 두 시점 사이에 기억·목표·계획 등이 어떻게 달라졌는가 |

구체적인 화면, 조회 도구, 검색 형식은 아직 정하지 않습니다. 전체 이력을 매번 원격 LLM에 보내는 방식도 전제하지 않습니다.

## 7. 예시

1. 첫 회차에서 여행 준비 요청을 인지하고 목표를 생성합니다. 출발일을 몰라 질문하고 해당 상태를 기록합니다.
2. 사용자 응답으로 다음 회차가 시작됩니다. 출발일 반영, 작업기억과 목표 조건 수정, 기존 기상 예약 교체를 각각 추적할 수 있습니다.
3. 이후 조사와 일정 초안 작성의 결과가 관련 회차·단계에 연결됩니다.
4. 목표가 종료되면 [목표 종료 보고서](목표-종료-보고서.md)가 이 경과와 산출물을 연결합니다.

## 8. 이후 구체화할 사항

- 단계 중 어느 시점에 상태를 확정하고 기록할지와 세부 기록의 깊이.
- 긴 대화 세션이나 장시간 작업의 중간 기록 단위.
- 저장·정정·조회 방식과 중단 시 기록 누락을 줄이는 방법.
- 이력의 보관 기간, 용량 관리, 사용자 삭제·내보내기와의 관계.
- LLM·사용자·개발자 각각의 열람 방식과 권한 범위.
