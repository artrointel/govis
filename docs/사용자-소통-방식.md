# 사용자 소통 방식

## 1. 기본 방향

비서는 여러 소통 방식을 지원하고, LLM이 현재 맥락과 소통 목적, 긴급도, 사용자에게 주는 부담을 고려하여 적절한 방식을 선택합니다.

‘사용자에게 말할 것인가’뿐 아니라 **어떻게 주의를 요청하고, 어떤 형태로 대화를 이어갈 것인가**도 능동적으로 판단합니다. 모든 소통이 메시지 한 번과 나중의 답변 한 번으로 끝나는 것은 아닙니다.

## 2. 지원할 소통 형태

| 형태 | 사용자 경험 | 비서의 선택 의도 |
| --- | --- | --- |
| 비동기 메시지 | 문자처럼 내용을 남기고 사용자가 나중에 응답 | 지금 대화할 필요 없이 정보나 질문을 전달 |
| 즉시 대화 세션 | 잠시 채팅을 열어 사용자와 여러 차례 이야기를 주고받음 | 연속적인 질문·설명·의견 교환으로 함께 상황을 정리 |
| 지속 알림을 통한 즉시 소통 요청 | 전화를 걸듯 주의를 요청하며 즉각적인 확인·응답을 유도 | 지체하기 어려운 상황에서 빠른 소통이 필요 |
| 조용한 메시지 | 소리 등으로 방해하지 않고 내용을 남겨 사용자가 원하는 때 확인·응답 | 유용한 내용은 전달하되 지금 사용자를 방해하지 않음 |

비동기 메시지와 조용한 메시지는 배타적인 종류가 아닙니다. 조용한 알림으로 비동기 메시지를 보낼 수 있습니다. 지속 알림은 실제 전화나 음성 통화 구현을 확정하는 의미가 아닙니다.

## 3. 선택할 요소

- **내용과 목적:** 단순 정보, 질문, 제안, 결과 보고, 확인 요청 등 무엇을 전달하는가.
- **긴급도:** 언제까지 사용자가 확인하거나 응답해야 의미가 있는가.
- **대화 형태:** 나중에 답해도 되는 메시지인가, 여러 번 주고받는 즉시 대화가 필요한가.
- **주의 요청 강도:** 조용히 남길지, 알릴지, 지속적으로 주의를 요청할지.
- **사용자 맥락:** 확인 가능한 현재 상황과 연락 선호에 비추어 적절한가.
- **사용 가능한 수단:** 실제 제공되는 접점과 사용자에게 허용된 방식인가.

긴급도, 대화 형태, 알림 강도는 서로 구분합니다. 연속 대화가 필요하다고 항상 강하게 알릴 필요는 없고, 조용히 보냈다고 중요하지 않은 내용이라는 뜻도 아닙니다.

## 4. 활동 루프와의 관계

### 비동기 소통

기존의 ‘질문을 남기고 회차를 마친 뒤, 응답으로 새 회차를 시작한다’는 흐름을 적용합니다. 서비스가 동작 가능한 상태에서 응답이 도착하면 기상하고, 기존 미래 기상 예약을 취소한 뒤 새 회차 마지막에 다시 정합니다.

### 즉시 대화 세션

능동제안 단계에서 즉시 대화 세션을 열어 사용자와 여러 차례 주고받는 방식도 지원합니다. 세션 안의 매 메시지를 반드시 전체 파이프라인의 새 회차로 해석하지는 않습니다.

대화 내용과 결과는 작업기억과 관련 목표에 반영할 맥락입니다. 세션이 언제 끝나는지, 세션 중 새 실행이 필요할 때 어떻게 활동 루프에 연결할지, 다음 기상 결정을 언제 갱신할지는 이후 구체화합니다. 기존의 여섯 단계 순서를 변경하거나 별도 활동 루프를 추가하는 결정은 아닙니다.

### 긴급한 소통 요청

빠른 확인·응답이 필요한 경우 지속 알림으로 소통을 요청할 수 있습니다. 응답 후에는 목적에 맞는 메시지 교환이나 즉시 대화로 이어질 수 있습니다. 지속 알림은 사용자 주의를 요청하는 방식이며 그 자체가 별도의 활동 파이프라인은 아닙니다.

## 5. 기억에 남길 내용

선택한 방식과 이유, 실제 전달·대화 여부, 질문과 답변, 합의하거나 변경된 사항, 남은 확인 사항을 기록합니다. 전달을 시도한 것과 사용자에게 확인·응답받은 것은 구분합니다.

## 6. 이후 구체화할 사항

- 소통 목적·긴급도·사용자 상황에 따른 선택 기준.
- 즉시 대화의 시작·수락·종료와 무응답 시의 처리.
- 지속 알림의 반복·중단 기준과 사용자의 거절·나중에 응답 선택.
- 조용한 메시지의 표시와 사용자가 응답할 수 있는 접점.
- 대화 중 들어오는 정보·새 작업과 활동 루프의 연결 방식.

현재는 지원 방향과 역할을 정의합니다. 접점별 기술, 구체적인 시간·횟수·판정 기준은 확정하지 않습니다.
