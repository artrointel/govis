# 작업계획 및 집행 모델

## 1. 정의와 목적

목표를 달성하기 위해 현 시점에 어떤 작업을 할지 LLM이 계획하고, 로컬 서비스의 도구를 통해 실제로 집행하는 단계입니다.

계획을 작성하는 데 그치지 않고 사용자에게 유용한 일을 진행하는 것이 핵심입니다. 비서가 로컬 PC에 상주한다는 것은 지속적인 실행 기반을 갖는다는 의미이며, 원격 LLM의 판단이 서비스와 도구를 통해 실행으로 이어집니다.

집행 제약은 이 모델의 중요한 명세입니다. 아래에는 사용자가 명시한 금지 예시와 후속 설계 항목을 구분해 기록하며, 상세 정책은 미정입니다.

## 2. 입력

- 목표 정의 모델에서 유지·갱신한 목표와 이번에 검토할 목표.
- 컨텍스트 변화분과 갱신된 작업기억.
- 기존 계획, 이미 수행한 작업과 미완료 작업.
- 사용 가능한 도구와 사용자가 허용한 활동 범위.
- 현재 시점, 사용자 상황과 작업에 필요한 조건.

## 3. 수행 내용

1. 목표를 위해 지금 수행할 가치가 있는 작업을 찾습니다.
2. 해당 작업의 목적, 필요한 정보, 순서와 예상 결과를 정리합니다.
3. 실행 제약과 사용자 확인 필요성을 검토합니다.
4. 허용된 작업을 도구로 수행하고 결과를 확인합니다.
5. 확인한 결과를 바탕으로 필요한 후속 작업을 판단합니다.
6. 실행 결과와 보류 사항을 능동제안 모델로 전달하고 작업공간에 남깁니다.

한 단계 안에서 계획·도구 사용·결과 확인을 반복할 수 있습니다. 다만 활동을 얼마나 이어갈지와 종료 조건은 추후 정합니다. 이번 회차에 수행할 필요가 없는 작업은 보류할 수 있습니다.

## 4. 실행 제약

### 사용자가 명시한 금지 행위 예시

- 사용자를 돕는다는 이유로 개인 정보를 외부 웹사이트나 서비스에 유출하는 행위.
- 사용자 대신 온라인 결제를 스스로 수행하는 행위.

목표 달성에 유리하다는 판단으로 이 제약을 우회하지 않습니다. 단순한 사용자 알림이나 계획 작성과 외부에 실제 영향을 주는 행동을 구분해야 합니다.

### 외부 정보 조회와 개인 정보 전달의 구분

거주 지역의 날씨를 조회하는 예시는 능동적으로 수행할 수 있는 유용한 작업입니다. 그러나 날씨 조회를 위해 사용자 이름, 통화내역, 상세 동선까지 외부로 전달해야 하는 것은 아닙니다. 필요한 조회 정보의 범위와 정밀도는 별도로 명세합니다.

또한 원격 LLM을 호출하는 것 자체도 선택한 맥락이 외부로 전달되는 경로입니다. ‘로컬 작업공간’과 ‘모든 데이터가 로컬에만 머무름’을 동일하게 취급하지 않습니다. 원격 LLM에 제공할 정보와 외부 도구에 보낼 정보의 범위는 각각 구체화해야 합니다.

### 상세 명세 항목 — 검토용 초안

| 항목 | 정할 내용 |
| --- | --- |
| 정보 접근 | 어떤 사용자 정보와 로컬 자료를 읽을 수 있는가 |
| 외부 전달 | 어떤 정보를 어떤 대상에 어떤 목적으로 보낼 수 있는가 |
| 로컬 변경 | 파일·설정 등의 변경과 삭제를 어디까지 허용할 것인가 |
| 외부 영향 | 게시·전송·예약 등 외부 상태를 바꾸는 행동을 어떻게 다룰 것인가 |
| 사용자 확인 | 어떤 행동 전에 확인이 필요한가, 확인의 유효 범위는 무엇인가 |
| 비용과 작업량 | 호출·도구 사용·활동 지속에 어떤 한도를 둘 것인가 |
| 중단과 재시도 | 실패·중단 시 재실행 가능한 작업과 확인이 필요한 작업은 무엇인가 |
| 실행 기록 | 실제로 무엇을 했고 어떤 결과를 확인했는지 어떻게 남길 것인가 |

위 표는 정책을 정하기 위한 항목입니다. 각 행위의 허용 여부를 일괄 확정한 것은 아닙니다.

## 5. 출력

- 목표와 연결된 작업 계획 및 이번 회차의 수행 범위.
- 실제 수행한 작업과 도구 결과의 요약.
- 새로 확인한 사실과 그 출처·유효 시점.
- 실패·보류·사용자 확인이 필요한 작업.
- 능동제안에서 검토할 정보와 가능한 대안.
- 다음 회차에 이어갈 작업과 필요한 조건.

계획만 작성한 작업은 실행 완료로 기록하지 않습니다. 도구가 성공했다고 하더라도 목표한 결과가 확인되었는지는 구분합니다.

## 6. 다른 모델과의 경계

- 목표의 정의와 이번 회차의 구체적인 작업 선택을 구분합니다.
- 조사나 준비 작업을 수행한 것만으로 사용자에게 알릴 필요가 생기는 것은 아닙니다.
- 사용자에게 먼저 전달할지와 실제 전달 내용은 능동제안 모델에서 판단합니다.
- 실행 전 정보나 확인이 필요한 작업은 보류하고 능동제안 단계에 질문·확인 요청을 전달합니다. 비동기 소통이라면 회차를 마치고, 사용자 답변으로 시작한 새 회차에서 첫 단계부터 검토한 뒤 작업 수행을 결정합니다. 즉시 대화 세션에서 답변을 주고받는 경우의 실행 연결은 이후 구체화하며, 대화를 했다는 이유로 집행 제약이 달라지지는 않습니다.

## 7. 예시

사용자가 체중 관리를 위해 저녁에 야외 운동을 한다는 맥락과 관련 목표가 있습니다. LLM은 ‘오늘 저녁 날씨가 운동 계획에 영향을 줄 수 있다’고 판단해 필요한 범위의 지역 날씨를 검색합니다.

비가 예상된다는 결과와 적용 지역·시간, 실내 운동 등의 대안을 정리해 능동제안 모델로 넘깁니다. 이 조사 자체가 온라인 결제나 개인 정보 전달을 허용하지는 않습니다.

## 8. 미정 사항

- 도구별 실행 제약과 허용·금지·확인 필요 행동의 상세 기준.
- 실행 제약을 실제로 강제하는 방식.
- 작업 진행 중 새 맥락에 따라 계획을 바꾸는 범위.
- 장시간 작업을 다음 회차로 넘기는 기준.
- 실패·중단 이후 외부 영향의 발생 여부를 확인하는 방식.
