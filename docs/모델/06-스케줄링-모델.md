# 스케줄링 모델

## 1. 정의와 목적

현재 활동의 마지막 단계에서 **LLM이 다음에 언제 다시 깨어나 전체 파이프라인을 수행할지 스스로 판단하고 결정하는 모델**입니다.

사용자의 생활과 목표에 관련된 다음 변화나 사건을 예상하고, 도움이 필요한 시점을 앞서 살필 수 있도록 다음 기상 시각을 기록합니다.

예약은 다른 계기가 없어도 스스로 다시 활동하기 위한 최소한의 기상 장치입니다. 모든 기상을 미래 타임스탬프 하나에 종속시키지 않습니다.

## 2. 입력

- 현재 시점과 이번 활동에 소요된 시간.
- 최신 컨텍스트와 작업기억, 유효한 목표.
- 작업의 완료·보류 상태와 아직 확인하지 못한 사항.
- 능동제안 결과와 사용자 응답 대기 여부.
- 사용자의 생활 패턴, 예정된 사건과 명시적인 시간 조건.
- 공통 맥락에서 함께 검토한 단·중·장기 목표와 기억.

## 3. 수행 내용

1. 다음에 사용자 상황이나 목표 진행에 변화가 있을 만한 사건을 찾습니다.
2. 그 변화 전에 준비하거나 다시 확인할 필요가 있는지 판단합니다.
3. 진행 중인 작업과 사용자 요청의 시간 조건을 함께 검토합니다.
4. 다음 기상 시점을 선택하고, 그때 무엇을 확인·수행할지 정리합니다.
5. 다음 기상 시각과 판단 이유를 작업공간에 기록합니다.
6. 서비스 프로세스가 해당 시점에 다음 회차를 시작할 수 있도록 결정을 전달합니다.

예상한 생활 패턴은 확정된 일정과 구분합니다. 이번에 선택한 다음 기상 시점도 이후 맥락에 따라 다시 판단할 수 있습니다.

## 4. 출력

| 항목 | 의미 |
| --- | --- |
| 다음 기상 시각 | 다음 회차를 시작할 타임스탬프 |
| 시각의 기준 | 시간대와 기준 시점 등 시각 해석에 필요한 정보 |
| 판단 이유 | 어떤 사용자 상황·목표·예상 사건을 고려했는지 |
| 다음 회차의 목적 | 다시 확인할 맥락과 이어갈 작업 |
| 판단의 전제 | 예상 일정, 사용자 응답 등 변경 가능성이 있는 조건 |

이 항목은 의미상의 명세입니다. 타임스탬프 형식이나 저장 기술은 아직 정하지 않습니다.

## 5. 서비스 프로세스와의 역할 구분

- **LLM의 스케줄링 모델:** 다음 기상 시점과 이유를 판단합니다.
- **상주 서비스 프로세스:** 결정을 보관하고, 예약이나 사용자 응답 등의 계기에 원격 LLM을 호출해 파이프라인을 시작합니다.

따라서 서비스가 실행할 예약과 LLM이 예약을 결정하는 판단을 구분합니다. 원격 LLM이 호출 없이 스스로 시간을 확인하며 깨어나는 구조를 뜻하지 않습니다.

### 유연한 기상과 예약 교체

- 서비스가 동작 가능한 상태에서 비동기 사용자 응답이 도착하면 예약 시점까지 기다리지 않고 즉시 기상합니다.
- 응답으로 기상할 때 기존 미래 기상 예약을 취소합니다. 새 회차는 상황 변화 파악부터 시작하고 마지막에 다음 기상 예약을 갱신합니다.
- 취소하는 것은 이전의 기상 예약입니다. 해당 예약과 관련 있던 목표·기한·반복 조건·확인할 일은 유지하여 새 회차에서 함께 검토합니다.
- PC가 꺼져 있거나 프로세스가 동작하지 않으면 그동안 LLM 활동도 일어나지 않습니다. 다시 동작하면 확보된 응답·새 맥락과 지난 예약을 현재 시점에서 재검토하고 다음 기상을 정합니다.
- 응답이 도착했다는 사건 자체는 기존 예약 취소로 사라지지 않으며, 새 회차의 입력으로 이어져야 합니다. 전달 경로나 보관 방식은 이후 정합니다.

이미 회차가 진행 중일 때의 응답 처리와 짧은 시간에 여러 사건이 발생했을 때의 처리 방식은 미정입니다. 별도 활동 루프를 중복 생성한다는 의미의 ‘즉시 기상’은 아닙니다.

즉시 대화 세션 안의 메시지 교환은 비동기 응답으로 새 회차를 여는 경우와 구분합니다. 매 메시지마다 전체 루프를 다시 시작하거나 기상 예약을 취소하는 규칙을 일괄 적용하지 않습니다. 세션 종료와 다음 기상 결정의 연결은 이후 정합니다.

## 6. 예시

17시에 깨어났고 사용자가 18시에 운동하는 경향이 있다면, LLM은 ‘운동 직전 상황을 확인하고 필요한 도움을 줄 시간’을 고려해 다음 기상을 17시 50분으로 정할 수 있습니다.

매일 10시 뉴스 요약을 요청받았다면, 결과를 준비하는 데 필요한 시간을 고려해 그보다 앞선 기상을 선택할 수 있습니다. 구체적으로 몇 분 전에 깨어날지는 아직 정하지 않습니다.

사용자와 대화하는 시점과 기상 시점은 같을 필요가 없습니다. 먼저 깨어나 조용히 준비한 뒤 정해진 시점에 결과를 전달하는 흐름도 향후 구체화할 수 있습니다.

## 7. 검토할 경계 조건 — 미정

- 최초 활동은 누가 어떤 기준으로 시작할지.
- 다음 기상 판단이 실패하거나 시각이 누락·과거로 지정된 경우.
- 너무 잦은 기상이나 장기간 깨어나지 않는 결정을 어떻게 다룰지.
- PC 종료·절전, 프로세스 중단 이후 지난 예약을 구체적으로 재평가하는 기준.
- 사용자 응답 외에 즉시 기상하게 할 사건의 범위와 판단 기준.
- 원격 LLM이나 도구 호출이 실패했을 때의 재시도 시점.
- 활동 도중 응답이 오거나 여러 기상 계기가 겹쳤을 때 중복 실행 없이 반영하는 방식.
- 사용자 시간대 변경과 기상·전달 시각 사이의 관계.

이 조건을 처리하기 위한 고정 주기나 기본값을 지금 확정하지는 않습니다. 스케줄링을 LLM이 판단한다는 구상을 유지하면서 서비스가 결정을 실행할 때 필요한 경계를 이후 설계합니다.
