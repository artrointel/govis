# 파이프라인 공통 명세

## 1. 공통 목적

> 사용자를 지속적으로 이해하고, 필요한 순간에 먼저 도움을 제안하며, 함께 목표를 이루어가는 개인 AI 비서를 만드는 프로젝트입니다.

각 모델은 이 목적을 달성하기 위한 작업에 관련된 내용만을 기반으로 동작합니다. 정보를 더 많이 수집하거나 작업을 더 많이 만드는 것 자체를 성과로 삼지 않습니다.

## 2. 공통 용어

| 용어 | 의미 |
| --- | --- |
| 모델 | 활동 파이프라인 안에서 고유한 책임을 갖는 작업 단계 |
| 파이프라인·활동 루프 | 공통 맥락 아래 여섯 단계를 순차 수행하고 다음 회차로 이어지는 하나의 반복 흐름 |
| 활동 회차 | 깨어나서 여섯 단계를 수행하고 다음 기상을 정하는 한 번의 활동 |
| 기상 | 서비스 프로세스가 원격 LLM을 호출해 활동을 시작하는 것 |
| 작업공간 | 여러 회차의 맥락과 목표, 작업, 결과를 이어가는 로컬 중심의 공간 |
| 컨텍스트 변화분 | 기준 시점 이후 새로 생겼거나 수정·취소된 관련 정보 |
| 컨텍스트 스테이징 | 변화분을 검토 가능한 상태로 임시 정리하는 것 |
| 작업기억 | 사용자 정보와 비서의 현재 작업 방향, 진행 상태, 후속 판단을 이어가는 기억 공간 |
| 목표 | 사용자에게 이루어주고자 하는 결과 또는 지속적으로 제공할 서비스 |
| 작업 | 목표를 위해 이번 시점에 수행하는 구체적인 행동 |
| 능동제안 | 사용자가 먼저 요청하지 않은 시점에 비서가 판단해 전달하는 정보·질문·제안 |
| 소통 방식 | 대화 형태와 주의 요청 강도, 접점을 조합한 사용자 소통 방법 |
| 즉시 대화 세션 | 잠시 채팅을 열어 사용자와 여러 차례 주고받는 연속 대화 |
| 활동 스냅샷 | 특정 회차·단계 시점의 상태와 전후 변화를 확인할 수 있는 기록 |
| 목표 종료 보고서 | 종료된 목표의 생성 배경·경과·결과·산출물을 정리해 보관하는 정적인 기록 |

작업기억을 ‘백엔드에서 맥락을 이어가는 공간’으로 부르는 것은 역할 설명입니다. 특정 저장 기술을 뜻하지 않습니다. 비서의 판단 기록은 다음 활동에 필요한 근거 요약, 결정, 불확실성, 진행 상태를 뜻하며, 내부 추론 전문 보관을 요구하지 않습니다.

## 3. 순차 실행과 단계 간 전달

| 단계 | 주로 받는 내용 | 다음 단계로 전달할 내용 |
| --- | --- | --- |
| 컨텍스트 인지 | 마지막 상호작용 시점, 기존 맥락, 접근 가능한 최근 정보 | 출처와 시점이 있는 변화분 및 확인하지 못한 영역 |
| 작업기억 | 변화분, 기존 작업기억 | 갱신된 사용자 맥락, 작업 방향, 미해결 사항 |
| 목표 정의 | 변화분, 갱신된 작업기억, 기존 목표와 사용자 요청 | 유지·갱신할 목표, 목표 후보, 우선 검토 대상 |
| 작업계획 및 집행 | 목표, 맥락, 도구, 실행 제약 | 계획과 실행 결과, 발견한 사실, 실패·보류·확인 필요 사항 |
| 능동제안 | 실행 결과, 목표, 사용자 상황과 최근 전달 이력 | 전달·보류 판단, 실제 전달 내용과 후속 확인 사항 |
| 스케줄링 | 앞 단계의 결과, 예상 사건, 남은 작업과 제약 | 다음 기상 시점, 선정 이유, 다음 회차의 확인 목적 |

이 표는 의미상의 전달 관계입니다. 데이터 형식이나 각 단계의 API를 확정하지 않습니다. 필요한 경우 이전 단계의 근거도 참조할 수 있습니다.

## 4. 공통 동작 원칙

- 사용자에게 필요한 정보와 작업인지 각 단계의 목적에 비추어 판단합니다.
- 관측한 사실, 사용자가 명시한 내용, LLM의 추론을 구분합니다.
- 변화가 없거나 도움이 불필요하다는 결론도 정상적인 결과입니다.
- 각 단계에서 할 일이 없으면 깊이 진행하지 않고 통과할 수 있습니다. 목표나 행동을 억지로 만들지 않습니다.
- 정보가 부족하거나 확인되지 않은 상황을 ‘문제없음’으로 바꾸어 기록하지 않습니다.
- 목표를 정의한 것, 작업을 계획한 것, 실제 실행한 것, 사용자에게 전달한 것을 구분합니다.
- 도움의 필요성 판단이 도구 사용 권한을 확대하지 않습니다.
- 실행이나 사용자 상호작용으로 맥락이 바뀌면 이후 회차에 이어지도록 남깁니다.

작업기억 모델은 회차 초반의 기억 검토·갱신을 담당합니다. 이후 단계에서 생긴 목표 변경, 실행·보류 결과, 실제 전달한 질문과 제안, 응답 대기 상태, 다음 기상 결정도 기억에 반영합니다. 초기 갱신만 수행하고 후속 결과를 누락해서는 안 됩니다. 단계별로 반영할지 회차 종료 시 정리할지는 미정이며, 별도 일곱 번째 판단 모델을 추가하지 않습니다.

질문이나 승인 요청은 능동제안 단계에서 전달합니다. 비동기 소통에서는 필요한 답변이 없는 작업을 보류하고 회차를 마칩니다. 이후 사용자 응답은 새 회차의 상황 변화로 받아들여 첫 단계부터 진행합니다.

소통은 비동기 교환으로 한정하지 않습니다. LLM이 맥락과 긴급도에 따라 조용한 메시지, 즉시 대화 세션, 지속 알림 등 적절한 방식을 선택합니다. 즉시 대화 세션 안에서는 여러 차례 주고받을 수 있으며, 매 메시지가 새 전체 회차를 시작해야 하는 것은 아닙니다. 세션과 회차의 구체적인 연결은 미정입니다. [사용자 소통 방식](../사용자-소통-방식.md)을 참조합니다.

비동기 응답으로 기상할 때 이전 미래 기상 예약을 취소하고 새 회차에서 다시 정합니다. 예약 취소는 관련 목표·기한·보류 작업의 삭제를 의미하지 않습니다. 응답이 없는 동안에도 다른 수행 가능한 작업은 진행할 수 있으며, 응답 대기는 서비스 전체의 정지를 의미하지 않습니다.

공통 맥락 아래 기억은 단·중·장기 관점을 구분해 보관하고, 판단할 때 관련 관점들을 함께 참조합니다. 기간별로 독립적인 활동 루프를 만들지 않습니다.

## 5. 회차를 이어가기 위한 기록과 스냅샷

매 기상과 단계별 변화는 [활동 이력과 스냅샷](../활동-이력과-스냅샷.md)으로 남깁니다. 변화 없이 통과한 단계도 확인할 수 있어야 합니다. 다음은 기록할 내용을 구체화하기 위한 항목이며, 구체적인 필드와 저장 구조는 아직 정하지 않습니다.

- 몇 번째 활동인지와 활동 시점, 이번에 기상한 계기.
- 이번 회차가 참조한 맥락의 범위와 확인하지 못한 정보.
- 변경한 작업기억과 목표, 그 근거의 요약.
- 실제로 실행한 작업과 확인된 결과.
- 사용자에게 전달했는지, 전달 또는 보류한 이유.
- 남은 작업과 다음 회차에 다시 확인할 사항.
- 다음 기상 시점과 판단 이유.

현재 작업기억이 갱신되더라도 이전 상태와 변화의 근거를 이력에서 확인할 수 있어야 합니다. 목표 종료 시에는 [목표 종료 보고서](../목표-종료-보고서.md)를 저장한 뒤 진행 중인 목표·작업 목록에서 정리합니다. 보고서와 스냅샷은 서로 연결하며, 기록 생성과 사용자에게 알리는 판단은 구분합니다.

## 6. 공통 미정 사항

- 각 단계의 세부 프롬프트와 명세 수준.
- 단계별 실패 시 이후 단계를 진행·보류하는 조건.
- 이미 회차가 진행 중일 때 사용자 응답이 들어오면 중복 회차 없이 반영하는 방식. 기상 요청의 우선순위·합류·중단 같은 세부 방식은 이후 정합니다.
- 회차 중단 후 재개 위치와 이미 수행한 작업의 재실행 방지 방식.
- 한 회차에서 사용할 시간·호출·작업량의 한도.
- 스냅샷·보고서의 구체적인 열람 방식과 작업공간에 대한 사용자 정정 반영 방식.

기간별 기억의 구분과 통합 참조는 [기간별 기억과 통합 판단](07-기간별-기억과-통합-판단.md)에서 다룹니다.
