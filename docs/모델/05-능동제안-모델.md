# 능동제안 모델

## 1. 정의와 목적

작업계획 및 집행 모델의 결과를 바탕으로, 지금 사용자에게 먼저 행동할 필요가 있는지 판단하고 실제 정보 전달·질문·제안까지 수행하는 단계입니다.

핵심은 유용한 일을 했다는 사실만으로 알림을 보내는 것이 아니라, **지금 이 내용을 사용자에게 전달하는 것이 도움이 되는지** 판단하는 것입니다.

전달 필요성뿐 아니라 적절한 소통 방식도 LLM이 선택합니다. 비동기 메시지, 즉시 대화 세션, 지속 알림을 통한 즉시 소통 요청, 조용한 메시지 등을 지원합니다. 상세한 개념 구분은 [사용자 소통 방식](../사용자-소통-방식.md)에 정리합니다.

## 2. 입력

- 이번 회차의 계획·집행 결과와 새로 확인한 사실.
- 사용자의 현재 맥락과 관련 목표.
- 전달할 수 있는 대안과 사용자에게 확인해야 할 사항.
- 최근 전달 내역과 사용자 반응, 확인 가능한 연락 선호.

## 3. 수행 내용

1. 실행 결과 중 사용자에게 의미가 있는 내용을 찾습니다.
2. 정보의 최신성·신뢰성과 사용자 상황과의 관련성을 검토합니다.
3. 지금 전달해야 하는지, 나중에 전달할지, 전달하지 않을지 판단합니다.
4. 소통 목적·긴급도·사용자 상황에 따라 대화 형태와 주의 요청 강도, 사용 가능한 접점을 선택합니다.
5. 사실과 제안, 질문 등을 구성해 실제로 전달하거나 즉시 대화 세션을 열어 여러 차례 주고받습니다.
6. 선택한 방식과 이유, 실제 소통 결과와 후속 확인 사항을 기록합니다.

구체적인 전달 수단은 아직 정하지 않았습니다. 제안 작성, 전달 시도, 전달 확인, 사용자의 확인·응답은 서로 다른 상태입니다. 긴급도와 대화 형태, 알림 강도도 구분하여 판단합니다.

## 4. 판단 항목 — 검토용 초안

| 항목 | 살펴볼 질문 |
| --- | --- |
| 관련성 | 현재 목표나 사용자 상황에 실제로 도움이 되는가 |
| 시의성 | 지금 알아야 하는가, 사용자가 행동할 시간이 남아 있는가 |
| 새로움 | 이미 전달했거나 사용자가 알고 있는 내용의 반복인가 |
| 근거 | 사실과 추론이 구분되어 있고 제안할 근거가 충분한가 |
| 방해 정도 | 지금 말을 걸 가치가 사용자의 부담보다 큰가 |
| 실행 가능성 | 사용자가 선택할 수 있는 구체적인 대안이나 다음 행동이 있는가 |

각 항목의 비중, 임계값, 조용한 시간대나 전달 빈도 규칙은 아직 정하지 않습니다.

## 5. 출력

- 지금 전달·추후 전달·전달 생략 등의 판단과 이유.
- 선택한 소통 방식·주의 요청 강도와 그 이유.
- 실제 사용자에게 전달한 내용 또는 보류한 내용.
- 전달 시점과 전달 결과.
- 사용자의 답변이나 승인을 기다리는 사항.
- 스케줄링에서 고려할 후속 확인 시점·조건.

이 구분은 초기 명세이며 고정된 상태값 목록은 아닙니다.

## 6. 다른 모델과의 경계

- 날씨 검색 같은 사전 작업은 작업계획 및 집행 모델에서 수행합니다.
- 이 단계는 결과를 바탕으로 사용자에게 먼저 다가갈지와 어떻게 전달할지를 담당합니다.
- 새로운 사용자 반응은 컨텍스트와 작업기억, 목표의 후속 갱신으로 연결합니다.
- 사용자에게 목표를 제안하거나 집행 전 확인을 요청하는 내용도 전달할 수 있습니다. 답변 대기 중 동일 요청의 반복 여부는 별도로 관리해야 합니다.
- 정보 부족으로 필요한 질문 자체도 이번 회차의 능동적인 사용자 소통입니다. 이를 위해 실행 단계 앞에 별도 소통 단계를 넣거나 단계 순서를 바꾸지 않습니다.
- 비동기 질문은 질문과 응답 대기 상태를 기억에 반영한 뒤 회차를 마칩니다. 사용자 응답이 도착하면 동작 가능한 서비스는 즉시 기상하여 새 회차의 상황 변화 파악부터 시작하고, 이전 미래 기상 예약을 취소한 뒤 마지막 단계에서 새 예약을 정합니다.
- 즉시 대화 세션은 이 단계에서 여러 차례 주고받을 수 있습니다. 매 메시지가 무조건 새로운 전체 회차를 시작하는 것은 아닙니다. 세션과 회차의 경계, 대화 중 실행이 필요할 때의 연결은 이후 구체화합니다.
- 사용자가 직접 요청한 정기 뉴스 전달은 자발적인 새 제안과 구분합니다. 이 단계를 거치더라도 명시적 전달 약속을 임의로 생략하지 않도록 규칙을 정해야 합니다.

## 7. 예시

평소 18시에 운동할 가능성이 있는데 그 시간대에 비가 예상됩니다. 비서는 ‘저녁 운동 시간대에 비가 예상됩니다. 오늘은 실내 운동을 하거나 시간을 앞당기는 방법이 있습니다’와 같이 사실과 대안을 함께 전달할 수 있습니다.

이미 같은 예보를 전달했고 상황이 달라지지 않았다면 다시 알리지 않는 판단도 가능합니다. 전달하지 않았더라도 확인한 결과와 판단은 다음 회차로 이어갑니다.

## 8. 미정 사항

- 사용자에게 다가가는 접점과 전달 확인 방식.
- 상황에 맞는 소통 방식 선택과 즉시 대화 세션의 관리 방식.
- 반복 제안 억제와 긴급 정보 전달 기준.
- 사용자 선호·거절·무응답을 이후 제안에 반영하는 방식.
- 정기 요청 결과와 자발적인 제안을 함께 다루는 규칙.
- 단·중·장기 관점에서 나온 관련 내용을 하나의 소통으로 조율하고 중복을 줄이는 방식.
