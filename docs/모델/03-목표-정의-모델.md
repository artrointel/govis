# 목표 정의 모델

## 1. 정의와 목적

컨텍스트 변화와 갱신된 작업기억을 바탕으로 사용자의 최근 상황·상태를 추론하고, 사용자를 위해 추구할 목표를 LLM이 정의·검토·갱신하는 단계입니다.

목표는 사용자가 직접 요청할 수도 있고, LLM이 필요성을 발견해 정의하거나 사용자에게 제안할 수도 있습니다. 매 회차 목표의 유효성과 진행 방향을 다시 살핍니다.

## 2. 입력

- 최신 컨텍스트 변화분과 작업기억.
- 기존 목표와 관련 작업의 진행 결과.
- 사용자의 직접 요청, 목표 제안에 대한 승인·수정·거절.
- 단·중·장기 각 관점에서 함께 참조할 관련 목표와 결과.

## 3. 목표가 생기는 경로

| 경로 | 예시 | 구분할 내용 |
| --- | --- | --- |
| 사용자 직접 요청 | ‘매일 아침 10시에 주요 뉴스 3개를 요약해서 알려줘’ | 명시적으로 요청한 내용과 시간·반복 조건 |
| LLM의 추론과 정의 | 운동 관련 맥락을 보고 운동 지속을 도울 필요성을 판단 | 사용자 의사를 직접 확인했는지와 추론 근거 |
| LLM 제안 후 사용자 승인 | 비서가 목표를 제안하고 사용자가 동의 | 승인한 범위와 사용자가 수정한 조건 |

LLM이 목표를 스스로 정의할 수 있다는 방향을 유지합니다. 다만 추론한 목표를 사용자의 명시적 의사로 기록하지는 않습니다. 어떤 목표를 사용자 확인 없이 활성화할 수 있는지는 별도로 구체화합니다.

목표에는 아래 출처·발생 경로·이유를 함께 기록합니다. 사용자 확인 여부도 남겨, 근거가 있다는 사실과 사용자가 동의했다는 사실을 구분합니다.

| 항목 | 기록할 의미 |
| --- | --- |
| 출처(source) | 관련 사용자 발언, 관측 데이터, 활동 결과 등 근거가 나온 곳과 시점 |
| 발생 경로(origin) | 사용자 직접 요청, LLM 추론, LLM 제안 후 사용자 승인 등 목표가 생긴 경로 |
| 이유(reason) | 현재 맥락에서 왜 이 목표가 사용자에게 도움이 된다고 판단했는지의 요약 |

목표를 수정할 때에도 새 출처·이유와 사용자 확인 상태를 반영합니다. 세 항목의 의미를 구분해 기록한다는 방향이며, 구체적인 데이터 필드 이름과 형식은 미정입니다.

## 4. 수행 내용

1. 기존 목표가 현재 맥락에서도 유효한지 검토합니다.
2. 사용자 요청과 최근 변화에서 새로운 목표 또는 수정 필요성을 찾습니다.
3. 각 목표의 의도, 원하는 결과, 관련 상황과 조건을 정리합니다.
4. 유지·수정할 목표와 새 후보, 재확인할 목표를 구분합니다.
5. 이번 회차에 작업으로 이어갈 목표를 작업계획 및 집행 모델에 전달합니다.

목표를 새로 만들 필요가 없다면 기존 목표를 유지할 수 있습니다. 목표 변경의 근거가 약하면 확인 과제로 남길 수 있습니다.

## 5. 목표에 담을 내용 — 검토용 초안

- 사용자를 위해 이루려는 결과 또는 제공할 서비스.
- 출처·발생 경로·이유와 관련 맥락. 위 구분에 따라 함께 기록합니다.
- 단·중·장기 시간 범위 및 다른 목표와의 관계.
- 시각·반복·기한 등 사용자가 지정한 조건.
- 사용자 확인 여부와 현재 유효성.
- 진행 상황, 최근 검토 결과와 다음 검토 사항.
- 달성·완료 또는 더 이상 추구하지 않을 조건.

상태 종류와 우선순위 규칙, 구체적인 필드는 아직 정하지 않습니다.

## 6. 다른 모델과의 경계

- ‘운동을 지속하도록 돕는다’는 목표와 ‘오늘 저녁 날씨를 검색한다’는 작업을 구분합니다.
- 목표에 매일 10시라는 조건이 있더라도 실제 다음 기상 시점은 마지막 스케줄링 모델이 준비 시간 등을 고려해 판단합니다.
- 목표 제안을 사용자에게 전달해야 한다면 능동제안 모델로 넘길 수 있습니다. 목표 후보를 기록한 것과 사용자에게 실제 전달한 것은 구분합니다.
- 목표가 있다고 해서 관련된 모든 행동이 허용되는 것은 아닙니다. 집행 제약은 별도로 적용합니다.
- 목표의 생성·변경·종료는 활동 스냅샷과 연결해 추적합니다. 종료 시에는 [목표 종료 보고서](../목표-종료-보고서.md)에 배경·경과·실제 결과·산출물을 남긴 뒤 진행 중인 목록에서 정리합니다. 보고서 제작은 새 일곱 번째 판단 모델이 아니라 목표 생애주기 전반의 공통 책임입니다.

## 7. 예시

‘매일 아침 10시에 주요 뉴스 3개를 요약해 알려줘’라는 요청은 일회성 검색 작업이 아니라 반복적으로 제공할 서비스 목표로 기록합니다. 이번 회차의 뉴스 수집·요약은 그 목표를 위한 개별 작업입니다.

체중 관리 사례에서는 사용자에게 확인된 목표인지, 생활 패턴만을 바탕으로 LLM이 추론한 후보인지 구분하여 기록합니다.

## 8. 미정 사항

- 추론한 목표의 활성화·승인 기준과 사용자 의사 확인 방식.
- 목표의 우선순위, 충돌·중복 처리, 중단·완료 조건.
- 반복 목표의 한 회차 완료와 목표 전체 종료의 구분.
- 단·중·장기 목표를 연결·분리하는 기준.
- 사용자 답변이 없는 목표 후보를 유지하거나 정리하는 기준.
