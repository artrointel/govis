# 컨텍스트 인지 모델

## 1. 정의와 목적

LLM이 지금 막 깨어난 상황에서 수행하는 첫 단계입니다. 사용자와의 마지막 상호작용 이후 어떤 최신 정보나 변화가 있는지 점검하고, 기존 맥락에 반영할 변화분을 찾아 스테이징합니다.

이 단계의 중심 질문은 **‘이전과 비교해 사용자의 상황에서 무엇이 달라졌는가?’**입니다.

## 2. 입력

- 현재 기상 시점과 기상 계기, 이번 회차에서 살펴볼 맥락의 범위.
- 사용자와의 마지막 상호작용 시점 및 이전에 파악한 맥락.
- 최근 사용자 대화와 사용자에게 전달했던 내용.
- 접근이 허용되고 실제로 제공되는 모바일 앱의 최근 개인화 데이터.
- 기존 정보의 수정·취소나 사용자 정정 사항.

이전 회차에 비서가 보낸 질문·승인 요청에 대한 응답도 새로운 상황 변화입니다. 사용자가 응답해 기상한 경우에도 이 첫 단계부터 시작하고, 어떤 보류 작업이나 목표에 대한 답변인지 함께 확인합니다.

모바일 데이터의 예시는 동선, 걸음 수, 최근 통화내역, GPS 기반 위치 변화입니다. 이는 향후 활용 가능한 정보의 예시이며, 현재 앱이 존재하거나 모든 정보를 수집할 수 있다는 전제는 아닙니다. 수집·조회 범위는 별도로 정합니다.

## 3. 수행 내용

1. 이번 회차에서 변화 여부를 살펴볼 시간과 정보 범위를 확인합니다.
2. 접근 가능한 최근 정보와 기존 맥락을 대조합니다.
3. 새로 생긴 정보, 달라진 정보, 취소되거나 유효하지 않게 된 정보를 구분합니다.
4. 사용자 이해와 목표 지원에 관련된 변화분을 임시 정리합니다.
5. 출처, 관측 시점, 불확실성과 확인하지 못한 정보도 함께 남깁니다.

## 4. 출력

다음 작업기억 모델이 검토할 수 있는 컨텍스트 변화분입니다.

| 항목 | 의미 |
| --- | --- |
| 변화 내용 | 새 정보, 변경·취소된 내용, 이전과 달라진 상태 |
| 출처와 시점 | 대화나 데이터의 출처, 실제 관측 시점 |
| 비교 기준 | 어떤 이전 정보 또는 시점과 비교했는지 |
| 관련성 | 사용자 맥락이나 목표와 어떤 관련이 있는지 |
| 확인 상태 | 관측 사실인지, 추가 해석·확인이 필요한지 |
| 정보 공백 | 접근 실패, 오래된 데이터, 아직 확인하지 못한 영역 |

이는 논리적인 정보 항목이며 구체적인 데이터 형식은 미정입니다.

## 5. 다른 모델과의 경계

- 스테이징한 내용을 모두 확정된 사용자 정보로 기록하지 않습니다. 기억에 어떻게 반영할지는 작업기억 모델이 판단합니다.
- 여기서 곧바로 사용자 목표를 확정하거나 실행 계획을 집행하지 않습니다.
- 정보를 불러오는 작업과 사용자에게 도움이 될 별도 조사·행동을 구분합니다. 운동을 위해 날씨를 새로 검색하는 예시는 작업계획 및 집행 모델에서 다룹니다.

## 6. 예시

최근 대화에서 사용자가 ‘오늘은 야근이 있어서 운동이 늦어질 것 같다’고 했습니다. 모바일 앱에는 당일 걸음 수와 최근 위치 정보가 들어와 있습니다.

이 모델은 발언과 관측 데이터를 변화분으로 정리합니다. 걸음 수가 적다는 사실만으로 운동을 포기했다고 단정하지 않고, 위치 정보가 오래되었다면 현재 위치로 취급하지 않습니다.

## 7. 미정 사항

- 마지막 상호작용과 마지막 컨텍스트 처리 시점이 다를 때의 비교 범위. 사용자와 대화가 없는 동안 여러 번 기상할 수 있으므로, 중복 검토와 누락 방지 기준이 필요합니다.
- 데이터별 최근 정보의 범위와 오래된 정보의 판정 기준.
- 중복·충돌 정보의 정리 방식과 조회 실패 시의 동작.
- 원본 데이터와 스테이징 정보의 보관 범위 및 기간.
